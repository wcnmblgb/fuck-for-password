# fuck-for-password

数字密码穷举 + 坐标校准工具（**C++ 版为当前维护版本**）。

> ⚠️ **Python 版已停止维护**，仅作为历史参考保留，不再更新；新功能只在 C++ 版维护。

在**自己拥有或已获授权**的设备、软件上找回忘记的数字密码：模拟鼠标点击逐个尝试
`0000`~`9999`，并通过屏幕某个像素点的颜色变化判断密码是否正确。

---

## 一、环境要求

### Python 版（已停止维护，仅存档）

| 项目 | 要求 |
|---|---|
| 系统 | Windows 7 / 10 / 11，32 位或 64 位 |
| Python | 3.6+（建议 3.8+） |
| 第三方库 | **无**。只需标准库 `ctypes`、`json`、`os`、`sys`、`time`，不用 `pip install` 任何东西 |
| 权限 | 普通用户；目标程序若以管理员运行，脚本也要以管理员运行 |

### C++ 版（维护中）

| 项目 | 要求 |
|---|---|
| 系统 | Windows 7 / 10 / 11，32 位或 64 位 |
| 编译器 | MinGW-w64（`g++`，C++17）或 MSVC（Visual Studio Build Tools） |
| 第三方库 | **无**。只链接 Windows 自带的 `user32`、`gdi32`、`gdiplus`、`shell32`、`ole32` |
| 建议 | 编译时加 `-static`，产物不依赖 MinGW 运行库，换机器可直接运行 |

用到的 Windows API：

- `SetCursorPos` / `SendInput` —— 移动鼠标、模拟点击
- `GetAsyncKeyState` —— 读取 ESC 状态（急停）
- `GetCursorPos` —— 校准抓点
- `GetPixel`（GDI）—— 读取屏幕像素颜色
- `GetDC` / `ReleaseDC` —— 屏幕设备上下文
- GDI+（`Gdiplus`）—— GUI 版绘制界面（圆角、渐变、图片）
- `SetProcessDPIAware` —— 高 DPI 下保证坐标与物理像素一致

## 三、速度设置

GUI 版主界面点 **【速度设置】**：

- **单轮总时长（毫秒）**：一轮 = 点 4 个数字 + 确定 + 清零，共 6 次点击。数值越小整体越快
- **高级选项**（默认关闭）：勾选后可单独设置
  - 每次点击按住时长
  - 两次点击之间的间隔

两者**双向联动**：

```
单轮总时长 = 6 ×（点击时长 + 间隔）+ 判定等待 + 清零等待
```

- 改总时长 → 按当前比例自动折算点击时长和间隔
- 改点击时长或间隔 → 总时长自动跟着更新

判定等待（默认 350ms）和清零等待（默认 30ms）是固定值，不参与加速。

改完点「确定」会立刻生效并写入 `coords.json`（字段 `round_ms` / `hold_ms` / `gap_ms`），下次启动自动读取。

## 三、编译 C++ 版

### 穷举主程序（控制台）

```
g++ -O2 -std=c++17 -static -o 穷举密码.exe 穷举密码.cpp -luser32 -lgdi32 -lgdiplus -lshell32 -lole32
```

### 校准工具（GUI，无控制台）

```
g++ -O2 -std=c++17 -static -mwindows -o 校准坐标.exe 校准坐标.cpp -luser32 -lgdi32 -lgdiplus -lshell32 -lole32
```

`-mwindows` 用于生成无控制台窗口的 GUI 程序；`-static` 必须加，否则运行时会缺
`libstdc++-6.dll` 之类（错误码 `0xC0000135`）。

MSVC 等价命令：

```
cl /nologo /O2 /std:c++17 /utf-8 /EHsc 穷举密码.cpp /link user32.lib gdi32.lib
cl /nologo /O2 /std:c++17 /utf-8 /EHsc 校准坐标.cpp /link user32.lib gdi32.lib gdiplus.lib shell32.lib ole32.lib /SUBSYSTEM:WINDOWS
```

> `/utf-8` 不能省，否则源码里的中文会在控制台显示成乱码。

## 四、使用流程

### 1. 校准坐标（只需一次）

把目标密码界面摆好、之后不要移动窗口，然后运行校准程序：

- **Python**：`python 校准坐标.py`
- **C++**：运行 `校准坐标.exe`

按提示依次把鼠标移到这些位置，每一项有 3 秒倒计时，结束自动记录：

```
数字 1、2、3 … 9、0  →  确定按钮  →  清零按钮  →  颜色监视点  →  失败弹窗关闭（可跳过）
```

结果写入 `coords.json`。

GUI 版还可以：

- 点列表任意一行 → 单独重抓该项
- **测试移动** → 鼠标依次停在每个已记录的点上，肉眼核对
- **保存配置** → 写回 `coords.json`

### 2. 运行穷举

- **Python**：`python 穷举密码.py`（可带起始密码，如 `python 穷举密码.py 1234`）
- **C++ 控制台**：`穷举密码.exe`，或 `穷举密码.exe 1234` 指定起始密码
- **C++ GUI**：点【开始穷举】，输入起始密码（默认 0000）

运行时程序会：

1. 点 4 个数字键
2. 点【确定】，等待判定
3. 读取颜色监视点的像素，与基准色比较
4. 点【清零】清空输入框，进入下一组

**急停**：按 `ESC`，或把鼠标甩到屏幕左上角。

## 五、颜色判定的原理

密码正确时密码轮盘会自动关闭，即屏幕上某个点的颜色会变。

- `watch_point`：监视点坐标
- `base_color`：基准色（轮盘打开状态下的颜色），留空则启动时自动采样
- `tolerance`：容差，单通道差值超过它就算「变色」，默认 30

命中后记入 `hits.txt`，默认**不停止**，继续跑完；想变色即停可把 `stop_on_hit` 改为 `true`。

> 选监视点的要点：落在 **轮盘关闭后颜色会明显变化、平时保持静止** 的位置。
> 如果落到了按钮高亮、动画区域，会产生大量误报。

## 六、配置项（`coords.json`）

```json
{
  "keys": { "1": [x, y], "2": [x, y], "...": [] },
  "submit": [x, y],
  "clear_point": [x, y],
  "watch_point": [x, y],
  "base_color": [r, g, b],
  "tolerance": 30,
  "stop_on_hit": false,
  "fail_close_point": null,
  "fail_close_key": null
}
```

| 字段 | 说明 |
|---|---|
| `keys` | 数字 0~9 的坐标 |
| `submit` | 确定按钮坐标；`null` 表示用回车提交 |
| `clear_point` | 清零按钮坐标（每轮必须清空，否则数字会叠加） |
| `watch_point` | 颜色监视点 |
| `base_color` | 监视点的基准颜色 |
| `tolerance` | 颜色容差 |
| `stop_on_hit` | 变色后是否停止 |
| `fail_close_point` | 失败弹窗关闭按钮坐标（可选） |
| `round_ms` | 单轮总时长（GUI 速度设置写入，仅记录用） |
| `hold_ms` | 每次点击按住时长（毫秒） |
| `gap_ms` | 两次点击之间间隔（毫秒） |

## 七、常见问题

**Q：第二组开始结果全错**
没配或没点「清零」，数字在输入框里叠加了。补齐 `clear_point`。

**Q：点击没反应**
目标程序可能以管理员权限运行，本程序也要用管理员身份启动（Windows 的 UIPI 会拦截跨权限的模拟输入）。

**Q：坐标偏移几十像素**
高 DPI 缩放问题。程序已调用 `SetProcessDPIAware()`，仍偏移就重新校准。

**Q：颜色检测一直不触发**
① 基准色采错了（必须在轮盘打开时采样）；② 监视点选在轮盘关闭后颜色不变的位置；③ `tolerance` 太大。

**Q：`hits.txt` 里一堆连续组合都被标记**
监视点选得不好，落到了会随悬停/动画变化的位置。换一个静态点或调大容差。
真正的答案通常是**时间最早的那一条**。

**Q：C++ 版双击闪退**
编译时漏了 `-static`，运行时会缺 DLL（错误码 `0xC0000135`）。重新编译时加上。
